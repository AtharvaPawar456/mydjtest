### Field writing guide

| JSON key              | Page heading        | What to write |
|-----------------------|---------------------|---------------|
| tech                  | Tech                | Stack in one line, commas (MCU/sensors OR languages/frameworks) |
| abstract              | Abstract            | Objective + approach + key tech + expected outcome (120–160 words) |
| keywords              | Keywords            | 12–20 distinct terms (domain, tech, application) |
| project_description   | Project Description | Problem → goals → method → who benefits (220–350 words) |
| project_features      | Project Features    | 8–12 short bullets of capabilities |
| hardware_components   | Specs → Hardware    | BOM-style list string |
| software_components   | Specs → Software    | IDE, languages, cloud, libs, OS |
| applications          | Applications        | Real places/use cases (5–8) |
| advantages            | Advantages          | Strengths (5–8) |
| limitations           | Limitations         | Honest prototype limits (4–6) |
| future_scope          | Future Scope        | Upgrades / research extensions (4–6) |
| conclusion            | Conclusion          | Wrap-up + impact + path forward (120–180 words) |
| highlighttitle        | Card / meta line    | Single compelling sentence |

Do not output Report Contents — the website injects that automatically.

NOTE (site field, not part of this JSON): Project document links (PPT/PDF/DOC)
are stored separately on the product as `documents` in the Django admin / edit form
(semicolon-separated URLs, optional Label|URL). Do not put raw file links only
inside prodinfo HTML unless asked.

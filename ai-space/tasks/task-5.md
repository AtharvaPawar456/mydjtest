## I4 - Improvements applied

**SQL filter optimization**
- `productlist`: count decoupled from row fetch (`.count()` instead of `len(queryset)`), and the list query now uses `.only(...)` to load just the 6 columns the card template renders instead of every large `TextField` (`gallery`, `ytlinks`, `prodinfo`, `prodtags`).
- `internship_listing`: collapsed 4 separate `COUNT(*)` queries into 1 `.aggregate()` call with conditional `Count()`; `total_intern_count` is now derived (`stipend_count + unstipend_count`) instead of queried. Also added `.only(...)` for the list-card fields.
- `internship_opportunities`: `load_opportunities()` (file read + parse) is now `@lru_cache`d — it was re-reading and re-parsing `intern-ops.txt` from disk on every single request regardless of filters. Restart the app (or call `load_opportunities.cache_clear()`) after editing that file.

**No full page reload on filter/search**
- Added `mainapp/static/mainapp/js/ajax-filters.js`: a small generic, dependency-free module. Any container marked `data-ajax-filter data-ajax-target="<selector>"` gets its internal links/GET-forms intercepted; clicks/submits `fetch()` the same URL with an `X-Requested-With: XMLHttpRequest` header, and the view responds with just the results partial instead of a full page, which replaces the target container's `innerHTML`. Browser history is kept in sync via `history.pushState`/`popstate` (back/forward still work), and it falls back to a normal full navigation if the fetch fails — progressive enhancement, not a hard requirement on JS.
- Applied to the three pages that had GET-param-driven filter/search UI (identified as the only ones in the app with this pattern):
  - **Products** (`productlist`) — search box + quick-filter tag chips. New partial: `ProductSection/_product_results.html`.
  - **Interns** (`internship_listing`) — stipend filter links. New partial: `InternSection/_intern_results.html`.
  - **Internship opportunities** (`internship_opportunities`) — stipend + track filter links. New partial: `InternSection/_opportunity_results.html`.
  - Each view now renders the partial template when `isAjaxRequest(request)` is true (checks the `X-Requested-With` header), otherwise the full page as before — verified both paths return correct, differently-shaped responses (see Dry run below).
  - Not converted: `our_team`, `viewAllShop`, `youtube_projects`, `accessoriesProjects`, `aicontentList` — these render their full unfiltered list with no GET-param filter UI today, so there was nothing to convert.

- Removed a duplicate local `from django.http import Http404` import inside `viewShop` (already imported at module level).

## I2 - Bugs found

### Critical / Security

- [ ] **1. Hardcoded `SECRET_KEY`** — `handmadeprojects/settings.py:25`. `SECRET_KEY` is committed to source control.
  **Fix:** Load from an env var (e.g. `os.environ["DJANGO_SECRET_KEY"]`), generate a fresh key for production, rotate the current one since it's already public.

- [ ] **2. `DEBUG = True` in production-style config** — `handmadeprojects/settings.py:28`. Alongside Render hostname handling, whitenoise, psycopg2, gunicorn. Leaks full tracebacks/settings on any unhandled exception.
  **Fix:** `DEBUG = os.environ.get("DJANGO_DEBUG", "False") == "True"`, default False.

- [ ] **3. Wildcard `ALLOWED_HOSTS`** — `handmadeprojects/settings.py:35`. `ALLOWED_HOSTS = ['*', "localhost", "127.0.0.1", 'mydjtest.onrender.com']` defeats Host-header validation, risking Host header injection (used in `seo_views.py` to build absolute sitemap/canonical URLs).
  **Fix:** Remove `'*'`; set explicit hosts from an env var.

- [ ] **4. Hardcoded-username admin gating** — `mainapp/views.py:593,602,630,669,709,748,780,835`. Repeated `if request.user.username != 'atharva':` instead of `is_staff`/permissions. Brittle and not scalable.
  **Fix:** Use `@staff_member_required` / `user_passes_test(lambda u: u.is_staff)` or real permission checks.

- [x] **5. Broken redirect target** — `mainapp/views.py:837` (`edit_hero_images`). Unauthorized branch does `return redirect('/HeroSection')`, a URL that doesn't exist (real route is `/dashboard/`).
  **Fix:** `return redirect('dashboard')` (named URL).

- [ ] **6. Stored-XSS risk via `|safe`** — `mainapp/templates/BusinessSection/shop.html:126,145`, `ProductSection/productinfo.html:149,185`, `InternSection/intern_profile.html:103`, `TeamSection/ourteam_profile.html:54`. Renders raw HTML from admin-editable `TextField`s.
  **Fix:** Sanitize with `bleach.clean()` before saving/rendering instead of trusting `|safe`.

- [ ] **7. No `.gitignore`, `db.sqlite3` committed** — repo root. No `.gitignore` anywhere; `db.sqlite3` sits in the project root (contains real user password hashes / contact messages if used as a working DB).
  **Fix:** Add `.gitignore` covering `db.sqlite3`, `__pycache__/`, `*.pyc`, `staticfiles/`, `media/`, `.env`; purge from git history and rotate exposed credentials if already committed.

- [x] **8. Password validators never invoked at registration** — `mainapp/views.py:96` (`register`). Calls `User.objects.create_user(...)` directly; `AUTH_PASSWORD_VALIDATORS` only fire through `UserCreationForm`, so weak passwords are accepted despite validators being configured.
  **Fix:** Call `django.contrib.auth.password_validation.validate_password(password)` explicitly and handle `ValidationError`.

- [x] **9. Unrestricted file upload handling** — `mainapp/views.py:639-654, 675-697, 724-726, 761-763`. Photos are read fully into memory and base64-encoded with no size limit, content-type check, or image verification.
  **Fix:** Enforce a max size, validate via Pillow (`Image.open(photo).verify()`) that the upload is really an image.

- **`edit_hero_images` view** (`mainapp/views/admin_views.py`) used a bare `@login_required` with no `login_url` argument, unlike every other protected view in the app (which all use `@login_required(login_url='login')`).
